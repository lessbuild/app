# Workspace credential inventory progress — 25 September 2026

Core now provides a Signal-themed credential inventory from the workspace dashboard and management page. It aggregates bounded, typed metadata from Deployer and Monitor providers, with product, credential type, and status filters plus pagination. Deployer rows describe the signed-in user's tokens for the reconciled Deployer organization, including legacy unscoped tokens that remain visible in Deployer for cleanup. Monitor rows require an active Core project/resource mapping and an owner/admin role in the mapped Monitor workspace; they include environment ingestion tokens and configured queue/heartbeat keys. Ambiguous environment mappings fail closed.

The provider boundary carries names, scopes, safe token prefixes where available, status, and timestamps only. Deployer token hashes are excluded from selected database columns; Monitor ingestion hashes are excluded, and queue/heartbeat hash columns are used only in source-side presence predicates. Core never receives the credential values. Each management link uses the shared-auth SSO handoff and returns to the source product, which continues to enforce its existing policies for create, rotate, reveal-once, and revoke operations. Analytics site IDs remain public collection identifiers rather than bearer credentials and link to Analytics setup.

Regression tests are authored for Core aggregation and product/status filtering, Monitor mapping and source-role checks, and secret/hash redaction. They have intentionally not been run, following the instruction to defer all tests until the complete unified plan is finished. PHP syntax checks and Pint passed, `core.workspace.credentials` is registered, and Blade cache compilation succeeded and was cleared.

This advances I13's shared inventory requirement. Centralized mutation APIs, complete endpoint and payload compatibility fixtures, expanded delivery/retry coverage, and representative public-client rehearsal remain open.
