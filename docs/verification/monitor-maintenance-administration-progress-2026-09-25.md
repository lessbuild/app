# Core Monitor maintenance administration — source checkpoint

Source commit `c04839a` adds a Signal maintenance-window page under each authorized workspace's Monitor administration. It lists Monitor-owned windows in bounded pages and delegates create, update, and removal to Monitor's existing `ChangeMaintenanceWindow` service through a narrow module provider. Times are entered and displayed in UTC; a window suppresses alert notifications while telemetry ingestion continues. The administration catalog links to the Core page, and Monitor's native page remains available for compatibility.

Reads require a current Core workspace membership and Monitor product grant, exactly one reconciled Core-to-Monitor user/workspace mapping, and native workspace view access. Mutations additionally require Core workspace management, verified native identity, native workspace update access, and an open account/workspace deletion state. Opaque, workspace-bound references identify rows. Updates and removal compare the rendered raw `updated_at` value inside the Monitor transaction after its SQLite write reservation. Removal requires explicit confirmation. Legacy second-precision versions are accepted; rows with a missing or malformed version remain visible but read-only.

Authored, unrun regressions cover owner CRUD, UTC values, 20-row pagination, Core/native role denial, revoked grants, ambiguous identities, foreign references, stale versions, missing removal confirmation, legacy timestamps, malformed version rows, deletion fences, and form-specific validation restoration. PHP lint, formatting, class autoload, four named routes, Blade compilation, module boundaries, and the staged diff check passed at the source checkpoint. Automated suites, migrations, live browser acceptance, and production cutover remain deferred under the user's instruction to finish the plan's source implementation first.
