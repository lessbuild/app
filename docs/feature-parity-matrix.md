# Unified platform feature-parity matrix

Prepared 23 September 2026 against the supplied source revisions below. This is a capability-level inventory from routes, controllers, models, migrations, jobs, commands, notifications, and configuration. It is a traceability checklist, not proof of behavioral parity: Monitor and Analytics source lives in peer modules, eligible production records have been imported into separate product databases and Core, and workflow-by-workflow evidence still needs to be recorded before cutover.

The counts describe the audited baseline and were produced from route declarations, so they are not unique customer features. Deployer routes, HTTP code, models, actions, jobs, notifications, commands, policies, services, scripts, product views, and migrations now reside under `app/Modules/Deployer`; `database/migrations` and the prior product-view paths remain compatibility symlinks. Shared Signal layouts and UI components remain in `resources/views`. Monitor and Analytics are imported under their modules. Their code defaults remain disabled until integration readiness, while the current production environment overrides both to enabled with Core authentication; that runtime setting is not evidence that their full feature parity is complete. Matrix rows record tested slices separately from remaining behavioral, role, data, and production-engine gates.

Durable write/worker acceptance across the production database engines remains open.
